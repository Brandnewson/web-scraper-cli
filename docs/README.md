# Docs Reference

This folder tracks *why* we made decisions, *what* we implemented, and *how* we
validated each phase.

## How to use

- Read `DELIVERY_GATES.md` at the start/end of each implementation step.
- Add one log entry per completed phase in `WORKLOG.md`.
- Keep entries short and evidence-based.
- For each entry, include:
  - `Why`: objective or requirement being satisfied
  - `What`: concrete changes made
  - `Validation`: test/benchmark evidence
  - `Notes`: constraints, deferrals, or follow-ups

## Current tracker

- `DELIVERY_GATES.md`: mandatory step-by-step rubric gate checklist
- `WORKLOG.md`: running implementation and validation history
- `ENGINEERING_RATIONALE.md`: reasons for technology/pattern/algorithm choices
